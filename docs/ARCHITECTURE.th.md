# สถาปัตยกรรมระบบ Life Cycle (Architecture Overview)

เอกสารสรุปสถาปัตยกรรมและการทำงานของแอปพลิเคชัน **Life Cycle** สำหรับการนำเสนอและการตอบคำถามเชิงเทคนิค

---

## 1. ภาพรวมของระบบ (System Overview)

Life Cycle เป็นระบบจัดตารางชีวิตและเป้าหมายสุขภาพประจำวัน ประกอบด้วย 3 ส่วนหลัก:

```
[ Frontend: Ionic React + Vite ]
               │
          HTTP / JWT (พอร์ต 5173 ผ่าน /api proxy)
               ▼
   [ Backend: Express + TypeScript ] (พอร์ต 3000)
       ├── คำนวณพลังงาน (Mifflin-St Jeor)
       ├── AI Service (Gemini API + Mock Mode)
       ├── ตัวขยายแผน 30 วัน (expand.ts)
       └── ตัวสร้างตารางเวลา (schedule.ts)
               │
          MySQL Protocol (mysql2 pool)
               ▼
      [ Database: MySQL 8.4 via Docker ] (พอร์ต 3306)
```

---

## 2. หลักการออกแบบที่สำคัญ (Design Principles)

1. **ตัวเลขทางโภชนาการคำนวณด้วยโค้ดเสมอ (Deterministic Nutrition Calculation)**
   - BMR คำนวณตามสูตร **Mifflin-St Jeor**:
     - ชาย: `10*kg + 6.25*cm - 5*age + 5`
     - หญิง: `10*kg + 6.25*cm - 5*age - 161`
   - TDEE คำนวณจาก BMR x Activity Factor (1.2 ถึง 1.9)
   - ปรับตามเป้าหมาย: ลดน้ำหนัก (-500 kcal), รักษาน้ำหนัก (+0 kcal), เพิ่มกล้ามเนื้อ (+300 kcal)
   - มีเพดานความปลอดภัย: แคลอรี่เป้าหมายจะไม่ต่ำกว่าค่า BMR ของผู้ใช้

2. **ตารางเวลารายวันสร้างด้วยโค้ด (`schedule.ts`)**
   - จัดสรรเวลานอน (23:00 - 07:00), มื้ออาหารตามจำนวนมื้อ (2-5 มื้อ), และเวลาออกกำลังกายตามช่วงเวลาว่างที่ผู้ใช้เลือก (เช้า หรือ เย็น) โดยไม่พึ่งพา AI เพื่อป้องกันข้อผิดพลาดด้านเวลา

3. **การขยายแผนเป็น 30 วัน (`expand.ts`)**
   - นำแผน 7 วันมาขยายตามหลักการฝึก Progressive Overload:
     - สัปดาห์ 1: แผนเริ่มต้น
     - สัปดาห์ 2: เพิ่ม 1 เซ็ต หรือเวลาฝึก
     - สัปดาห์ 3: เพิ่มจำนวนครั้งและการฝึก
     - สัปดาห์ 4: Deload พักฟื้นกล้ามเนื้อ (ลดปริมาณลง ~30%)
     - วันที่ 29-30: ปรับสมดุลสะท้อนผลการฝึก

4. **ความพร้อมใช้งานและการสำรองข้อมูล (Offline & Mock Reliability)**
   - รองรับ `AI_MOCK=true` เพื่อการทดสอบและการ Demo ได้อย่างเสถียร แม้ไม่มีการเชื่อมต่ออินเทอร์เน็ตหรือไม่มี Gemini API Key
   - มี Fallback Template ภาษาไทยคุณภาพสูง รองรับเมื่อ AI เกิดข้อผิดพลาดหรือเกินโควตา Rate Limit

5. **กฎความปลอดภัยและข้อจำกัด (No Emoji Constraint)**
   - ห้ามใช้ Emoji ในทุกส่วนของระบบ ทั้งฝั่ง UI, โค้ด และคำตอบของ AI
   - ฝั่ง Backend มีฟังก์ชัน `removeEmojis()` ด้วย Regular Expression สำหรับลบอักขระ Pictographic ก่อนจัดเก็บและแสดงผล

## 3. โครงสร้างฐานข้อมูล (Database Schema)

- `users`: จัดเก็บข้อมูลบัญชีผู้ใช้ อีเมล และรหัสผ่านที่เข้ารหัสด้วย `bcryptjs`
- `profiles`: จัดเก็บข้อมูลร่างกาย เพศ อายุ น้ำหนัก ส่วนสูง ไลฟ์สไตล์ BMR, TDEE, Target Kcal
- `plans`: จัดเก็บประวัติแผนงานสุขภาพ โดยผูกกับผู้ใช้และสถานะการใช้งาน (`is_active`)
- `plan_days`: จัดเก็บรายละเอียดเนื้อหาแผนรายวันทั้ง 30 วันในรูปแบบ JSON (ท่าออกกำลังกาย มื้ออาหาร ตารางเวลา) พร้อมฟิลด์ `completed_at`
- `chat_messages`: จัดเก็บประวัติการสนทนาระหว่างผู้ใช้และที่ปรึกษา AI

---

## 4. ผลการทดสอบ (Quality Assurance)

- Unit Tests: ผ่านการทดสอบทั้งหมด 11 รายการ ครอบคลุมฟังก์ชันคำนวณพลังงาน, ตัวสร้างตารางเวลา, การขยายแผน 30 วัน และตัวกรอง Emoji
- Frontend: ผ่านการตรวจสอบประเภทและคอมไพล์สำเร็จด้วย Vite และ TypeScript Strict Mode
